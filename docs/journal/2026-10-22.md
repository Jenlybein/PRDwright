## 本次踩到并修掉的两个真 bug（都是静默丢数据）

1. ⚠️ `formatException` 是 **`Formatter`** 的方法，`Handler` 上没有 → 任何带 `exc_info`
   的日志在 `emit` 里抛 AttributeError，被 logging 吞掉，**出错的日志恰好没入库**。
   单测漏了这条路径，是全量用例逼出来的。修法：handler 持一个 `logging.Formatter()`。
2. ⚠️ 后台线程等队列时一次等到 `interval` 结束 → 停止信号最坏要等满一个间隔（配 10 秒就是 10 秒），
   关服务时丢最后一批。修法：`_collect` 把等待切成 ≤50ms 小段（`min(remaining, 0.05)`）。
   （这个也是「队列满」用例在单独跑通过、全量跑失败的根因。）

### ⚠️ 本次修正了一处初稿判断：「撤销自己」不该算独立规则（ADR-043）

初稿把「不能撤销自己」当成一条规则，实现时发现**站不住**：
- 管理员交接/临时让渡是真实场景；只要还有别的管理员，撤销自己是正常且**可逆**的卸任。
- 两条规则在 HTTP 路径上**必然重合**（操作者是管理员时「最后一位」只可能是他自己）→ 互相遮蔽、报错打架。
现在：**规则只有一条**（`auth_service.set_admin` 独家实现「不能撤销最后一位管理员」），
后台与 `auth_cli.py demote` **共用同一份实现**（两条路各写一遍，迟早有一处漏改，后台就成了绕过不变式的后门）。
「撤销自己」不被单独拦，但**删号/停用自己**仍单独拦 403（那两个会毁掉或冻结自己的账号，性质不同）。
后台侧用 `FORBIDDEN`(403) 而非 `AUTH_FAILED`(401)——401 在前端意味着「该登录了」，这里登录也没用。

### ⚠️ 另一个真 bug：`sayFail` 期望异常对象，调用点传的是字符串

`messageOf` 只认 `ApiError`；把已取好的字符串再丢给它 → 认不出 → 被兜底文案覆盖一次，
管理员看到的永远是「操作失败」而不是后端给的理由。修法：`sayFail(message: string)` 收字符串，**不要再套 `messageOf`**。

### ⚠️ 端到端冒烟发现的缺口（单测没覆盖）

`PATCH /api/admin/users/{id}/admin`（授予/撤销管理员）**原本不存在**——CLI 能任命但后台不能，
意味着任命第二个管理员必须绕到命令行。已补上接口 + 前端按钮 + 5 条用例。
单测全绿却漏掉这个接口，说明「接口清单」这类事只能靠真实 HTTP 链路兜。

## 管理后台改为「只允许管理员账号登入」，权限不足提示「账号不存在」（ADR-049）

原状：后台登录复用 `/api/auth/login`（谁都能登），登录后再敲 `/api/admin/me` 判身份，非管理员停在 403 无权限页。

改法（三处口径统一）：
- 后端新增 `POST /api/admin/login`（`_PUBLIC_EXACT` 精确白名单），走 `auth_service.login(..., require_admin=True)`：
  **先验密码、再判 is_admin**；非管理员 401「账号不存在」，不记失败次数、**不签发会话、不顶掉主站会话**。
  密码错/不存在仍是「用户名或密码错误」，停用仍是「该账号已被停用」。
- `require_admin` 仍 403 `FORBIDDEN`，但 `detail` 改「账号不存在」。
- 管理端会话收敛为 `unknown|anonymous|admin`（`user` 档与 `ForbiddenView.vue` 一并删除），
  非管理员与未登录落在同一页（登录页 + 后端那句「账号不存在」）；`login()` 成功后不再补问 `/api/admin/me`。
- Cookie 下发 + 渐进延时抽到 **`api/login_flow.py`**（`set_session_cookie` / `wait_login_delay` / `_sleep`），
  两条登录入口共用一份；`test_login_lockout`、`test_admin_erasure` 的 monkeypatch 点随之挪到 `login_flow._sleep`。

⚠️ 顺序就是安全：先验密码再判 `is_admin`，否则「这个用户名是不是管理员」不需要密码就能问出来。
⚠️ 也不能「先 login 再判身份」——那会把人在主站上的会话 `replace()` 掉，等于「去后台登了一次被踢出主站」。

## v5 部署与上线：架构文档 + ADR + roadmap（纯文档，零代码改动）

读了旧的三篇部署文档（`C:\MyApps\Obsidian\basestote\实际项目\HarnessPRD\4.部署与上线\`），**参考结构、按现状重判**，产出 `docs/architecture/v5/` 四份：`README.md` / `ARCHITECTURE.md`（644 行）/ `ADR.md`（ADR-054~059）/ `roadmap.md`。

**六条拍板（ADR-054 ~ 059）**
1. **部署形态 = 单域名 + 路径前缀**（用户端 `/`、管理端 `/admin/`、API `/api/`）。否决子域的硬理由：后端 `set_cookie` **没设 `domain`** → Cookie 是 host-only → 跨子域「后台登录了、调 API 仍 401」；同域则 CORS 根本不参与、Cookie 天然共享。
2. **单 worker 是硬约束**（推翻旧文档的 `gunicorn -w 2`）：`_RUNTIMES`、`JobBus._subscribers`（源码注释原文「仅进程内，单实例」）、runtime_config 5s 缓存、SQLite 连接。不引 gunicorn（唯一价值就是多 worker）。三条推论：只起一个进程 / 重启会中断在飞任务（`reap_orphans`）→ 发布前排空 / 迁移与重启是同一动作。
3. **四目录分离**：`/opt/prdwright`（代码，可替换）· `/var/lib/prdwright`（DB）· `/var/www/prdwright/{user,admin}`（静态，可重建）· `/var/log/prdwright`（日志，可丢）+ `/etc/prdwright/{backend.env,master.key}`（600）。
4. **回滚 = 恢复备份，不是反向迁移**（迁移纪律是「只追加」，回退代码后是「新结构 + 旧代码」）。
5. **备份用 `VACUUM INTO` / `.backup`，不能 `cp`**（开了 WAL）；主密钥随备份同批且**保留每一把**（旧备份要旧密钥）；恢复演练是验收项。
6. **SSE 保活双保险**：Nginx `proxy_buffering off` + `read_timeout 1800s` + `gzip off`（零代码，必做）；服务端 `: ping` 心跳（防中间网关，可选，ADR-059）。

**查代码查出来的部署硬事实（别再猜）**
- `requires-python >= 3.12`、`.python-version 3.12` → Ubuntu 22.04 自带 3.10 **不够**（旧文档说 3.10 够，那是 v1）。
- 两个前端 `engines.node` = `^22.18.0 || >=24.12.0`（Vite 8）。
- 无 `requirements.txt` → 依赖真源 `pyproject.toml` + `uv.lock` → `uv sync --frozen --no-dev`；uvicorn 随 `fastapi[standard]` 已在锁里。
- ⚠️ `PRDWRIGHT_MASTER_KEY_PATH` 走 **`os.environ`** → 写 `.env` **读不到**，必须 systemd `EnvironmentFile`；`PRDWRIGHT_SKILLS_DIR` 走 `lookup_env`（两条路都通）。这是 `skill_registry` 已踩过的同类坑。
- `api/sse.py` 已自带 `X-Accel-Buffering: no`（与 Nginx 的 `proxy_buffering off` 是两道保险），但**没有心跳**。
- `frontend_admin` 未设 `base`、`createWebHistory()` 无参 → 挂 `/admin/` 必须改两处（Vue Router 的 `normalizeBase()` 兜底 `/`，**不跟随 Vite 的 base**）。
- `/health` 无 `/api` 前缀、在鉴权白名单、恒返回 200（`ok`/`degraded` 两档）。

**排期**：T0 目标机 → T1 后端起来 → T2 前端+Nginx+SSE → T3 域名 HTTPS → T4 备份与恢复演练 → T5 发布脚本与回滚演练。后端业务代码预期**零改动**（唯一例外是可选项 SSE 心跳）。
