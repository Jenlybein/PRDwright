# ADR-020：RAG 闸门从「只读展示」改为整条移除

> 源：v2 层（原 `docs/architecture/v2/ADR.md`，已并入本目录）｜ [索引](./README.md)

**状态**：Accepted（2026-10-15 裁决，随 R2-T9 立项；删除动作在 T9-3 / T9-4 落地）

### Context

ADR-011 定下了生成前的双闸门：闸门 1 摘要 Diff、闸门 2 RAG 接口规范检索（本地词法检索 `core/api_doc_knowledge.json`，挑前 5 条 → `RagResultPanel` 让用户勾选）。R2 立项时（`ARCHITECTURE.md` §4.4）曾裁决**保留**闸门 2、只把「阻塞式确认」降级为「只读展示」，理由是「让用户知道模型参考了什么」有价值。

那个理由本身成立，但**它把两件不同的事混在了一起**。闸门 2 注入的是**固定不变的团队规范**（14 条、约 6000 字），不是每次生成都需要用户重新审一遍的临时素材。对一份静态资产要求逐条确认，不是「可见性」，是不必要的摩擦；而真正的可见性诉求（这份文档参考了哪套规范）另有更完整的承载方式。

同时，「只挑前 5 条」这件事本身是**用不确定性换取省下来的几千 token**——规范总量全量注入也远低于预算上限（12 万），而挑漏一条，那次生成的接口文档就少了对齐依据，且**从输出上看不出来**。

### Options

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| A. 维持原样（阻塞式确认 + 挑前 5 条） | 零改动 | 每次生成多一次无意义的人工确认；漏挑静默 |
| B. 原定方案（降级为只读展示 + 保留检索） | 去掉阻塞、保留「参考了什么」 | 检索代码（分词 / 打分 / 阈值）继续要养；**漏挑仍然是静默的**；只读面板仍是每次生成途中的一次打断 |
| **C. 整条移除，规范改由技能包全量注入（推荐）** | 点生成直接开始；注入内容可预期、无抖动；少一条路径与一份代码 | 注入 token 变多（约 6000 字，仍远低于预算）；用户不能再用「不勾选」表达异议 |
| D. 换成向量检索 | 语义召回比词法强 | 规范只有 14 条，为一个固定小集合引入 embedding + 向量库，是拿复杂度换一个不需要的精度 |

### Decision

**选 C。**

1. **规范迁入技能包、全量注入**：`core/api_doc_knowledge.json` 的 14 条迁成 `skills/api-docs-generator/` 下可读的 md，与 PRD 走同一条注入管线。**全量比检索更稳定也更可预期**——钱不是问题，一致性才是。
2. **删除检索实现、检索接口、以及请求里携带的「用户勾选结果」字段**，不留一条「以后可能用得上」的旁路：留着它就有两条真相，规范改了哪条生效会变成要读代码才能回答的问题。
3. **前端删掉确认页组件、相关状态与 `RagHit` 类型**，点「生成接口文档」直接开始。删状态机里的 `rag-preview` 登记时要**同步改四处**（`ViewState` / `VIEW_STATES` / `STEP_OF_STATE` / `STATE_DOWNGRADE`），否则状态机会指向一个不存在的页面。
4. **可见性由回执承担，而不是由勾选面板承担**：`run_summary.injected_skills` 已经记录技能包名、版本与内容指纹（ADR-017）。它回答的是「这份文档按哪一套规范写的」，比「列 5 条让用户看一眼」更完整，而且不阻塞、不打断。
5. **闸门 1（摘要 Diff）不动**。它是**用户输入**的确认，用户确实需要看见自己的话被理解成了什么；而闸门 2 是**静态资产的注入**，两者不是一回事。这条区别正是原来那版裁决没分清的地方。

### Consequences

- **变容易**：生成接口文档从「检索 → 展示 → 勾选 → 继续」变成一步；规范全量在场，不会再有「这次恰好没挑到某条」的抖动；少一份需要维护的检索代码与一个前端组件。
- **变困难**：注入的 token 变多——约 6000 字，相对预算上限可忽略，但它意味着**规范总量将来不能无节制增长**，这份资产需要保持精炼；用户对某条规范有异议时不能再靠不勾选绕过，得直接改技能包文件（这本来也更对：规范是团队资产，不该每次生成现场裁剪）。
- **中立**：这不是「RAG 没用」，而是**它的适用条件不成立**——检索解决的问题是「候选集远超上下文预算」，而这里候选集只有 14 条。将来规范真的长到装不下时，正确的做法是重新引入检索，而不是怀念现在这条只挑 5 条、还不告诉人挑了哪 5 条的实现。
