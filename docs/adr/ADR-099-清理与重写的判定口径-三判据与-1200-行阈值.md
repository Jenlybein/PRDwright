# ADR-099：清理与重写的判定口径——三判据 + 单文件 1200 行阈值

**状态**：已定（v8 清理轮，2026-11-02）。清单落点 `docs/architecture/v8/CLEANUP.md`。

### 背景

"清理多余代码和死代码"这句话天然含糊：同一个仓库里它有四种东西可以被算进去——
①零引用的死代码；②退役但还在库里的列；③文档写了但仓库没有的悬空声明；④两个工程里长得像的实现。
不先分清楚就会出两种事故：把活的代码删了（构建红），或把"清死代码"做成"顺手重构"（范围爆炸、不可逆面变大）。

同时，"重写到什么程度"需要一个能说停的刻度。用函数行数当刻度在本仓库会失真：
Vue 的 composable 与 Pinia 的 `defineStore` setup 函数天然等于整个模块（实测 `useDocumentPipeline` 1543 行、
`useSolutionsStore` 648 行），按"单函数 >250 行"筛出来 7 个，其中 6 个是这类 setup 函数。

### 决策

1. **沿用 `CLEANUP.md` §1 的三判据**（无任何代码读它 + 删了用例不变红 + 不需改业务逻辑），三条同时满足才删。
2. **"重复实现"不算多余**：`frontend/` 与 `frontend_admin/` 的零共享是 ADR-039 的决定，
   把它当"多余"等于用清理之名做重构。判据 3 已明文把重构排除在外。
3. **重写阈值只看单文件行数 > 1200**，函数口径作废；"实在拆不动的就不拆"优先于"压到 1200 以内"。
4. **重写走 TDD**：先补覆盖再改结构；行为不变由全量用例证明；补的用例只覆盖原本没覆盖的分支。
5. **不可逆动作单独成笔**：删列（`solutions.data`、`model_providers.builtin`）与其余清理分开，
   且必须在"备份 → 迁移 → 结构对拍 → 全量"同一个窗口内完成。

### 理由

- **三判据的价值在于它已经挡住了最容易吵的两类**：`paste_prd_text` 这种"看着老但仍在读写"的，
  和"删它要改逻辑"的。临时立一套新标准不会更准，只会重新吵一遍。
- **函数口径作废是因为它会把"重写整个 store"伪装成"拆一个函数"**。
  文件口径（>1200）筛出来的是 10 个文件，其中后端 3 个、前端 7 个，规模和风险都可预期；
  函数口径筛出来的是 6 个 store/composable，动它们等于动前端骨架。
- **TDD 是因为重写没有别的东西能证明"没搞坏"**。这个仓库的测试有 1014 例、全量约 85 秒，
  先补再改的成本远低于改完发现行为变了。
- **分开成笔是因为可逆性不同**：删文件可以 `git revert`，删列不能（旧代码读不到列会启动失败，
  回滚方式是恢复备份）。混在一笔里会让"回退粒度"变粗。

### 关键约束

- 每次删除前**自己 grep**，不拿文档当证据：`AppDialog.vue` 被 ADR-015 写成"零外部引用"，
  实际 `ReviewStage.vue:7` 正在 import；照文档删会构建失败。反向的 `isApiError` 也同理——
  ADR-012 说它是判据，实际零调用、`useJob.ts:379` 用 `instanceof` 内联替代了。
- 扫描工具只报候选，不做裁决：`vulture --min-confidence 80` 实测跑出 **0 条**（假安全感），
  放低到 60% 的 122 条里真死的只有 1 条，误报比 121:1（路由、LangChain 覆盖点、模型字段、测试装置 helper）。
- 工具**临时装**，不写进 `pyproject.toml` / `package.json`——用只跑一次的工具换一个新的尾巴不值得。

### 被否决的方案

| 方案 | 理由 |
| --- | --- |
| 放宽判据，把"需改业务逻辑"的也纳入清理 | 那就不再是可回退的清理，而是重构；验收方式与分批方式都得换 |
| 把两个前端工程的重复实现合并 | 推翻 ADR-039；且"相似"不等于"多余"，合并会引入跨工程耦合 |
| 用"单函数 >250 行"当重写刻度 | 6/7 命中都是 Vue setup 函数，等于把"重写整个 store"当成"拆一个函数" |
| 删掉 v1~v7 历史文档层 | 实测层间重复 0~0.4%、体积只 1.1MB，删它是删证据不是清冗余 |
| 把 `vulture`/`knip` 写进依赖并挂 CI | 一次性清理换一个长期尾巴；改为把命令与复核结论写回清单留档 |

### 推论

- 本轮重写范围定为后端 3 个文件：`job_service.py`（1633）、`prd_section_writer.py`（1420）、`schemas.py`（1321）。
  `document_service.py`（1144）与前端三个文件（1627 / 1269 / 1201）**本轮不动**。
- 唯一一对 ≥30 行完全重复（`prd_section_writer.py` 553-585 ↔ 739-771，33 行）是否抽取，
  留到重写 W2 时一并决定，不在清理阶段动。
- 验收基线按实测：**1014 例**（工作区）/ **986 例**（HEAD）；`def test_` 文本计数 890 与收集数不是同一个数。
