# ADR-049：管理后台只接受管理员账号登录，权限不足一律「账号不存在」

> 源：v4 层（原 `docs/architecture/v4/ADR.md`，已并入本目录）｜ [索引](./README.md)

### Status

Accepted（2026-10-22）

### Context

v4 时管理后台的登录**复用**用户端那条 `POST /api/auth/login`：谁都能登进去，
进去之后前端再敲一次 `/api/admin/me` 判身份，非管理员停在「无权限页」。三个问题：

1. **越权入口在登录这一步就没关上。** 两个前端共用同一份 Cookie，普通账号在后台
   登录页输对密码会**真的登进主站**——后台顺手帮人登录了另一个产品，而那人当时
   只是「想看看能不能进后台」。
2. **无权限页把「账号存在」说出了口。** 它写着「已登录为 alice，但该账号不是平台
   管理员」。对运维对外的口径（后台只给管理员用）来说，这句话是反向的信息泄露：
   任何拿到一份普通凭据的人都能确认「这个用户名在系统里确实存在」。
3. 需求层面已经定调：后台只允许管理员账号登入，权限不足提示「账号不存在」。

三个候选：

| 方案 | 做法 | 否决理由 |
| --- | --- | --- |
| A 只改文案 | 无权限页改写「账号不存在」 | 后端仍然谁都能登进后台，文案是假的；且「登录后才发现」这一步没消除 |
| **B 登录入口判身份** | 新增 `POST /api/admin/login`，判完身份再决定是否签发会话 | —— |
| C 403 改 401 | 让「不是管理员」与「未登录」在服务端也不可分 | 401/403 的分工是前端「去登录」与「身份不行」的唯一判据，全仓十几条用例与文档都按它写；收益只是少一个状态码，代价是排查时连服务端都分不清「会话过期」与「撤了管理员」 |

### Decision

取 **B**，并配套把四处口径统一：

1. **`POST /api/admin/login` 是后台唯一的登录入口**，注册进中间件的白名单（精确路径，
   不给 `/api/admin` 整个前缀开口子——前缀放行会让将来新增的管理接口默默变成公开接口）。
   它调用 `auth_service.login(..., require_admin=True)`：
   - **先验密码、再判 `is_admin`**。顺序反过来会让「这个用户名是不是管理员」变成一个
     不需要密码就能问出来的问题，等于送出一份管理员名单。
   - 密码正确但不是管理员 → 401「账号不存在」，**不记登录失败次数**（凭据本来有效，
     与爆破无关）、**不签发会话**、**不动他在主站上的那条会话**。
   - 密码错/用户不存在仍是「用户名或密码错误」，停用仍是「该账号已被停用」——
     能走到这两句的人还没证明自己是谁，口径不变。
2. **`require_admin` 仍是 403 `FORBIDDEN`，detail 改「账号不存在」**。已登录的非管理员
   直接敲管理接口时，也不该再被告知「你存在、只是不够格」。
3. **管理端会话收敛为三阶段** `unknown | anonymous | admin`，删掉无权限页。非管理员与
   未登录**落到同一页**（登录页），区别只是页面上多一句后端给的「账号不存在」。
   `unknown` 仍然不能猜——猜成 anonymous 会让管理员每次刷新被踢一次。
4. **Cookie 下发与渐进延时抽到 `api/login_flow.py`**，用户端与后台两条登录入口共用一份。
   写两份的代价不是重复几行，而是「一处改了 `secure` / `samesite`，另一处忘了改」——
   症状是管理端登录后立刻掉线，而排查会先怀疑会话表。

### 本期不做

| 本期不做 | 理由 |
| --- | --- |
| 给后台登录单独一套失败计数（`admin:` 前缀或按 IP） | 现有按用户名计数已经压住爆破；分开要动 `login_failures` 的键结构，而收益（避免一个人在主站被延时）很小 |
| 主站与后台各发一份 Cookie | 不签发就已经达到「失败不影响主站」，再拆一份反而多出「同一个人两套会话」的状态 |
| 管理员二次验证（TOTP） | 独立课题，与「谁能进这个入口」正交 |
| 后台登录失败也记审计 | 失败尝试里大量是打错密码；审计表留给「人做成了什么」 |

### Consequences

- **变容易**：后台只有两种可见状态（登录页 / 后台），少一整页与一整段分支；
  普通账号再也不会「在后台顺手登进主站」。
- **变困难 / 必须记住**：
  - 非管理员会在登录页看到「账号不存在」，而他可能正是主站的老用户，会来问
    「我账号是不是没了？」。这是**刻意的取舍**（对外只承认管理员账号），
    运维口径必须与之一致；页面上不要补一句「你可能只是没权限」——那等于把
    「账号存在」又说回去了。
  - 会话被撤销管理员之后（例如在另一台设备上被降权），他会直接回到登录页而不是
    某一页「你已无权限」，且不会被告知原因。
  - `test_login_lockout` 等用例的 monkeypatch 点从 `api/auth.py::_sleep` 挪到
    `api/login_flow.py::_sleep`；以后新增登录入口也必须走这个模块，否则等于给爆破
    开一条无成本通道（用例 `test_admin_login_waits_before_checking` 就是钉这个）。
- **测试陷阱（真踩过 / 想得到）**：
  - 只断言状态码会漏掉「拒绝了登录，但把人在主站上的会话顶掉了」——写成「先
    `auth_service.login` 再判 `is_admin`」就是这个后果。补的
    `test_rejected_login_does_not_kick_the_user_off_the_main_app` 对照的是**旧 Cookie
    还能不能用**，而不是「本次响应有没有 Cookie」。
  - 断言「没有下发凭据」要看响应头里没有 `set-cookie`，不能看「客户端当前没带
    Cookie」（后者在已登录的客户端里永远为真，看着像断言、其实什么都没验）。
