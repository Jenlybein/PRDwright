# ADR 0002：审核结论随版本保存，按结论修复，输入一律由服务端取

- 编号：**0002**
- 状态：已采纳（文档先行；代码在后续提交里落地）
- 范围：审核结论的存放与生命周期；「修复」「重新审核」两个任务动作；生成与修复的输入来源；交付页的进入判据

---

## 决策

1. **审核结论随文档版本保存，一版一条。** 结论 = 判定（通过／有问题）、逐条问题与严重度、一句总结、是否改写、失败章节、审核时间。它挂在被审的那一版正文上，**重新审核覆盖同一条**；只在审阅页显示**当前版本**那一条。**审核没跑成不写结论**——没有结论不等于通过，界面照实标「审核失败」。
2. **新增两个任务动作。**「修复」= 按当前版本的审核结论重写正文，**追加新版本**（正文与结论同批写入）；同一任务内再**只审一次、不再改写**。「重新审核」= 只产结论、**不碰正文、不追加版本**。两者与生成管线共用同一段审核代码。
3. **生成、修复、重新审核的输入一律由服务端从库里取。** 库内产物取当前版本正文；导入入口的材料取方案行上保存的那几份录入文本；PRD 的需求输入（结构化摘要、自由文本需求、需求澄清历史）同样由服务端取。**请求体不再携带上游正文与需求正文。**
4. **「一键更新」= 用当前上游重新生成被点的那一份**（沿用该文档的审核配置），不新增任务种类。
5. **交付页不再由「完成」按钮把关：齐备即可进入。** 判据由入口模式决定（完整流程与快捷流程三份、导入入口只有提示词）；三份齐备时全应用提示一次（每方案每会话一次），**不自动跳转**。

---

## 背景

- 结论今天只活在 SSE 订阅里，刷新即失（代码注释与约定文档都写明「不持久化」）。没有结论，「按结论修复」无从谈起，用户只能整份重新生成——这正是「审核」这一环此前只算「提示」不算「能力」的原因。
- 审核结论与正文是同一时刻的两个事实：正文一改，结论就不再描述它。把结论挂在版本上，让「哪一份正文被审成什么样」成为可查记录，而不是一段会话内记忆。
- 上游正文一直由前端随请求传（生成接口文档传 PRD、生成提示词传 PRD + 接口文档），而后端同时维护着当前版本。两份「上游」迟早不一致；而「修复要看得见 PRD 全文」这条要求，让「前端副本是不是最新的」变成必须回答的问题。**输入只有一个来源，才谈得上上下文窗口是确定的。**

---

## 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 独立审核表（每次审核一行） | 与「一版一条、只在审阅页显示当前版本」的展示口径冲突；修复要引用的正是「这一版的那条结论」，版本上的一列就是它的自然键 |
| 结论只存最新一条（不带版本） | 同一方案的多次审核会互相覆盖；而审核与修复都需要「这一版被审成什么样」 |
| 塞进版本已有的 `metadata` | 那里是上游锚点的语义域；混入评审后，读的人无法判断一个键属于锚点还是属于评审 |
| 复用 `auto_clarify` / `optimize` 做修复 | 二者都是「覆盖当前版本」，而修复要追加新版本；一个 kind 两套版本策略，只能靠隐藏开关分叉 |
| 前端连发「修复」「重审」两个任务 | 中间必然出现「正文已换、结论还是旧的」窗口，正是本轮要消除的错位 |
| 让前端继续传上游（含「给了就用」） | 仍是双真源；导入材料本来就不入库，更需要一个明确的服务端来源 |
| 结论里存被审正文的指纹、不一致就标「已过期」 | 本轮明确不做过期判定：多一处状态与文案，而修复入口已按「有问题」把关 |
| 审核失败写一条「未通过」占位 | 把失败伪装成判定；失败就是没有结论 |
| 交付页在三份齐备时自动跳转 | 会抢走用户正在编辑的页面；改成「解锁入口 + 提示一次」 |

---

## 后果

- **迁移只加列**（nullable）：旧文档与旧版本读出来是「未审核」，不回填历史（历史上从未存过）。
- **请求体是一次破坏性收口**：旧前端多带的字段会被忽略；文档类任务缺方案、或导入入口的材料尚未落库时，返回明确 400，而不是空跑一次生成。
- 旧的非任务生成通道随之改签名（收方案、不再收上游正文），避免留下第二条绕过库的写入路径。
- **串行链路补发汇总结论**，`rewritten` 如实汇总；否则「PRD 能不能修复」会随并发度配置漂。
- 修复的上下文是**全量注入**（PRD 全文 / PRD + 接口文档全文），超预算走既有告警，不静默截断。
- **结论的写入是条件写**：被审正文在建任务那一刻快照，收尾时只写「当前版本指纹仍等于它」的那一版；不一致 → 任务失败、不写、也不覆盖已有结论。这与「按正文变化判定结论过期」不同：指纹只在**这一次写入**里用，不进结论、不新增状态；留下的是「没写成」而不是「一条标着已过期的结论」。
- 审核结论入库后，刷新、换设备、重连看到的是同一条结论；它不再依赖某一次订阅。
- 交付页的进入判据与入口模式绑定：导入入口只要求提示词一份，不因「导入」被锁在永远达不到的条件上。
