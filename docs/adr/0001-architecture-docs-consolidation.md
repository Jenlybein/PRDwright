# ADR 0001：把按层演进史换成单一现状文档 + 决策档案

- 编号：**0001**（决策档案从 0001 重新开始；旧 `ADR-001~099` 只在 git 历史里，仓库内不再有那些文件）
- 状态：已采纳
- 范围：仓库里的架构文档形态与**架构决策**的归档方式

---

## 决策

把 v1~v9 九个按层演进的目录压成一版**现状文档**：[`../architecture/ARCHITECTURE.md`](../architecture/ARCHITECTURE.md) 正向写「目标 → 范围（含本期不做）→ 设计 → 契约 → 取舍」，收齐现行架构、C-V9-1~10 与 C-D1~C-D6、已接受的风险与否决的方案；承重的专题内容（库结构勘察实测数据、方言可移植性台账、恢复演练要求）整段搬进该文档的附录，不留在 git 历史里当唯一依据。九层各留一行摘要（主题 + 关键取舍）作为演进索引，阶段规模与界碑独占 [`../architecture/README.md`](../architecture/README.md)（**时间线真源**），不重复写两遍。

同时重新建立 [`docs/adr/`](./) 决策档案目录，**只记这一条**关于文档重组的架构决策；生成任务相关的取舍写进现状文档的「取舍」节，不另立档案。九层目录删除，仍指向它们的 18 处外部引用逐条改到真实存在的新落点。

编号从 **0001 重新开始**：旧 `ADR-001~099` 曾在一次清理中整体移除，只在 git 历史里；接着旧编号会让后来的人去找已删除的文件。新目录与旧编号没有继承关系。

---

## 背景

九层文档是按演进分期长出来的：同一类结论散在多层里，读者既要判断「哪一层说的算」，又会在文档被删后照旧路径找文件。报告里出现过的失真（把 25 写成 30、11 写成 6、18 写成 92、把「加列」当单向门）也和这种「多处各写一遍」的形态有关。此前决策记录被整体移除，「决策与否决理由不再单独归档」成了旧口径，结论只能靠各层正文与 issue 历史去找，而层本身又即将删除。

---

## 被否决的方案

### 保留按层演进史

**否决理由**：

1. **没有唯一的现状**：九层各有一套 `ARCHITECTURE.md`，后来的人要先判断「哪一层说的算」；同一契约在多处抄写必然分叉，这是已确认的失真来源。
2. **引用会悬空**：全仓 92 条指向九层文档的引用里有 18 条在九层之外；只要删任何一层，这些引用就指向不存在的路径，而「文档写出的路径 `ls` 必须能看见」是本仓库的铁律。
3. **承重内容会被带走**：库结构实测、方言台账与恢复演练要求只活在 v8 / v7 的附录里；留在原地就得永远保留九层，删掉就只剩 git 历史当唯一依据。
4. **演进史不等于架构文档**：阶段规模、界碑与失真清单是 git 事实，归时间线真源；把历史与现状并排存放，等于让「曾经怎么想」和「现在怎么做」争同一份权威。

演进史本身没有丢：九行摘要表保留主题与关键取舍，[`README.md`](../architecture/README.md) §2 / §3 / §4 / §5 保留阶段总表、v2 七波重写、已确认的失真与复核方法，更早的细节仍在 git 历史与 issue 历史里。

### 其他一并否决的做法

| 做法 | 否决理由 |
| --- | --- |
| 把决策散写回各层正文、不建决策档案 | 「为什么换掉按层演进史」是跨层的架构决策，没有属于它的层；不归档就会再次随某次清理消失 |
| 为生成任务相关的取舍再立一条档案 | 那些取舍属于现状文档「取舍」节；档案不为容易反悔的决定越立越碎 |
| 沿用旧 `ADR-001~099` 编号 | 旧文件已删除，续号会让人去找 git 历史里已不存在的文件 |
| 九层摘要表重复阶段规模与界碑 | 时间线真源独占这些数字，重复写两遍正是失真来源 |
| 在仓库里存一份规格文件或临时工单目录 | 规格与票住在 GitHub Issues，仓库内不另存 |

## 后果

- 维护者打开仓库只有一处可读的架构结论；契约编号 C-V9-1~10 / C-D1~C-D6 在现状文档「契约」节集中可查。
- 三段承重专题整段可在现状文档附录 A / B / C 找到，不依赖 git 历史。
- 九层目录删除；18 处外部引用（含两处后端代码注释、清理守卫、部署说明、约定文档与根说明）改到真实落点；`AGENTS.md` 与 `docs/agents/` 的旧口径改指现状文档与 `docs/adr/`。
- **取消单文件 >1200 行阈值、改以接缝为依据**：这条拆分依据的变更写在现状文档 §5.4（取代 v8 附录 A §5 的 W1 口径），不在本档案另立一条决策。
- 决策档案目录后续若新增条目，须是真正的跨层架构决策，编号顺延，不为每个实施取舍建档。
