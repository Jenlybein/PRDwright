# ADR-090：容器形态 = 两个服务、两个镜像

> 源：v8 层（原 `docs/architecture/v8/ADR.md`，已并入本目录）｜ [索引](./README.md)

**状态**：已定（v8 / T18.5）。

### 背景

两种摆法：

1. 一个容器里跑 Nginx + uvicorn（supervisord 或 s6）；
2. 前后端各一个镜像：`web`（Nginx + 两个前端 dist）与 `api`（uvicorn + SQLite）。

### 决策

**取 ②**。理由与"性能"无关，与失败语义有关：

- 两个进程的重启策略不同。合并后，`nginx -s reload` 或 Nginx 崩溃会连带杀掉
  `api`，而 `api` 里跑着 LLM 生成任务；
- 资源画像不同。Nginx 的内存是常量，`api` 随生成任务波动；
- 日志形态不同。Nginx 的 access log 与应用的轮转日志混在一个 stdout 里，
  排障时要靠前缀区分。

配套：

- 宿主机只映射 `web:80`；`api:8000` 只 `expose`，由 `web` 反代（C-V8-3）；
- 不加 DB 容器——本期数据库仍是文件库，独立 DB 服务没有对象。换库那次它会成为第三个服务。

### 被否决的方案

| 方案 | 理由 |
|---|---|
| 单容器 + supervisord | 重启 Nginx 会杀掉生成任务；两个进程的失败语义被强行合并 |
| 每个前端一个 Nginx 容器 | 两个前端共用同一个域与同一份 Nginx 配置，拆开只会多一层反代 |
| 引入 k8s | 单机规模，且副本恒为 1（C-V8-1），k8s 的调度能力用不上 |
