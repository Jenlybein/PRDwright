# ADR-093：前端只允许相对路径，不引入构建期基址

> 源：v8 层（原 `docs/architecture/v8/ADR.md`，已并入本目录）｜ [索引](./README.md)

**状态**：已定（v8 / T18.5）。

### 背景

Vite 的 `import.meta.env.VITE_*` 是**构建期字符串替换**，不是运行期注入。
把它做成"容器启动时用环境变量指定 API 地址"，在 Vite 里做不到。

现状（已核实）：两个前端都是同源设计，`services/api.ts` 的 `baseURL` 是 `'/'`，
请求全部走 `/api/...`。所以这条约束目前**天然满足**。

### 决策

**把"必须用相对路径"写进契约（C-V8-5）**，而不是写进某个配置。

三条推论：

1. 不新增任何 `VITE_API_BASE` 一类的变量。有它就会出现"`docker run -e` 改了不生效"
   的错觉，而排查这个错觉要花掉比它省下的更多时间。
2. 换域名不需要重新构建镜像——Nginx 与 API 同源，前端不知道自己在哪个域下。
3. 如果将来前端要独立域名（比如 CDN），那是**另一个决策**：要么接受构建期注入，
   要么改成运行期读取 `/config.json`。届时按那次的需求重判，不要提前铺路。

### 被否决的方案

| 方案 | 理由 |
|---|---|
| 构建期注入 `VITE_API_BASE` | 一个镜像只能对应一个环境，与"镜像可搬运"直接冲突 |
| 运行期读 `window.__CONFIG__` | 需要 Nginx 生成 `config.js` 或挂载文件；本期没有多环境需求，属于提前抽象 |
