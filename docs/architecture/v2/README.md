## v2 的边界（明确没做，由 v3 承接）

一次「长文生成」在 v2 里仍是**乐观流程**：

1. **中断即全丢**——章节中间态是 `PrdSectionWriter.stream()` 里的局部变量，断网 / 关页就没了。
2. **供应商单点**——`llm_factory.get_llm()` 只构造一个模型，挂了就整条链路失败。
3. **成本不可见**——没有任何 token 打点，`/health` 只会回 `{"status":"ok"}`。

另有一项与生成无关、不影响功能的前端收敛未完成（细节见本层 `ARCHITECTURE.md` 主题 / 操作落点两节的「实施现状」）：
`dark:` 变体仍有 101 处 / 19 文件残留；`ui/` 里的 `AppDialog` / `AppToast` / `AppEmpty` / `AppInput` 已建但零外部引用。

## v2 是怎么走过来的（七波，按 git 提交）

v2 的净增代码（+22776 行）约为 v1 全部代码（+5891 行）的 **4 倍**，是一次**重写**而非补齐
（`26f2b49` 的提交信息明写「复用 App 多阶段流程」）：

1. **10-12 技能包**：prd-generator（工作流 / 字段契约 / 模板 / 写作规范）落地并接入 PRD 生成。
2. **10-12 前端换心**：`AppV2` 重写（+3858）。
3. **10-12 双闸门**：澄清专用人设 + 摘要回填 Diff + 接口规范检索（+2696）。
4. **10-13 生成质量**：分章节生成 + 三入口（+5559 / −3120，本阶段最大提交）。
5. **10-13 产品化**：登录 + 默认拒绝鉴权（+3675）、方案持久化（+3504）。
6. **10-13 前端体系**：组件库收口、三层主题令牌、底栏统一、part 事件驱动、提示词归后端（合计约 +4150）。
7. **10-14 护栏**：CI、品牌更名、错误码化、流式去重、版本收口（合计约 +1950）。

**护栏是最后一天才补的**——这是 v2 的真实顺序，也是 v3 要把可靠性前置的理由。
