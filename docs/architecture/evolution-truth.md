# 架构真相还原（基于 git 提交实测）

> 本文只认 git 提交，不认记忆与文档自述。
> 之所以需要它：现有架构叙述（ADR 状态、roadmap 盘点、版本分期）混用了
> **「当时写了什么」**与**「当时有什么」**，按提交逐条核对后发现了若干系统性失真。
> 本文是三层的**时间线真源**；`v1/` `v2/` `v3/` 三个文件夹只放各层的结论。

## 1. 还原方法

- **阶段界碑用仓库里的显式标记**：提交 `1c65e94 "V1版本开发结束"`（2026-10-10）是全仓库唯一的版本界碑，
  不是靠文档内容推断的。
- **能力的出现时间以 `--diff-filter=A` 的首次出现提交为准**，而不是以文档声称的状态为准。
- **规模用 `--shortstat`**，用来判断某阶段是「增补」还是「重写」。

### 3.3 v1 的定位

**一次性流程原型**：能问（问卷）、能聊（SSE 澄清）、能出三份文档（PRD / 接口文档 / 提示词）、
能流式看结果。会话随服务端进程结束、进度靠前端快照恢复——这就是「一次性」的含义，
也是它把全部复杂度押在「验证主链路」上的直接结果。完整设计见 `v1/ARCHITECTURE.md`。
