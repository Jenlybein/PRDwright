> ⚠️ T00 排在最前，且它不产出一行业务代码：它产出的是「那些失败
> 到底是测试的错还是产品的错」。这个答案会改变 T02 及之后所有任务的形态。
>
> **T00 与 T02a 已完成，结论：34 个失败 = 18 个已证测试缺陷 + 16 个待定（倾向测试缺陷）
> + 0 个确证产品缺陷。** 因此本期按测试重构推进，不必单列一个修 bug 阶段。
> 但 16 条待定必须在施工期按「**先改测试 → 仍红再查源码**」分流——
> 默认全部改测试，会把真实回归「修」成绿灯，那比红着更糟。

## ADR-054~059 为什么是空号

本层立项时，v5 阶段主题由「部署与上线」改为「测试重构」。原部署文档已由用户
**迁移到仓库之外**，本仓不再保留副本、也不再安排重建。

那六条部署决策的编号作为**预留墓碑**保留 —— ADR 编号是身份，不是时序
（ADR-042 被 053 取代后 042 也不重编号），所以本层 ADR 从 **060** 起。
六条各是什么见 `ADR.md` 的 ADR-070 摘要表：**那里只为说明空号的来历，不是待办**。

## 与 v4 的关系

v5 不改 v4 定型的任何业务行为。它对三个工程的产品代码是零侵入的
（唯一例外是 T10 的两份 `vitest.config.ts` 与 `backend/pyproject.toml`，
改的是测试配置，不是产品配置）。

本期动的全部是测试侧资产，分四类：

| 类别 | 涉及 | 性质 |
| --- | --- | --- |
| CI 编排 | `.github/workflows/ci.yml` | 补一个 job + 加一条时长护栏 |
| 后端测试装置 | `backend/tests/conftest.py`、`backend/pyproject.toml`（+`uv.lock`） | 提速：**不改夹具**，改默认并行（ADR-071） |
| 后端测试用例 | 54 个 `test_*.py` + 新增 2 个文件 | 分层标记、清理、补缺口 |
| 前端测试 | `frontend/src/__tests__/`、`frontend_admin/` | 共享状态治理、coverage 开关 |

> v4 的 ADR-039~053 全部继续有效。其中 ADR-053（密钥加密入库）引入的
> `reveal-key` 等接口，其安全用例在本期 T06 补齐。
