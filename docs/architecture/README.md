## 2. 阶段总表（按 git 实测）

**算法**：本文采用 `git diff --shortstat <界碑A> <界碑B>`，即「两个界碑之间的快照差异」。
**不是** `git log --shortstat` 逐提交累加——两者差很远（v2 累加得 `316 files / +27333`，快照差是 `120 / +22776`）。

| 阶段 | 区间 | 提交数 | 规模（`diff --shortstat`） | 界碑 |
| --- | --- | --- | --- | --- |
| **v1** | 10-03 ~ 10-10 | **17** ✓ | **不可复核**（见注） | `1c65e94` V1版本开发结束 |
| （空档） | 10-11 | 0 | — | 无提交 |
| **v2** | 10-12 ~ 10-14 | **25** ✓ | `120 files, +22776 / −2099` ✓ | `b78de90`（tag `v2.0.0`） |
| **v3**（记账到 `e494e90`） | 10-14 ~ 10-16 | **34** ✓ | `131 files, +26224 / −2986` ✓ | `e494e90` |
| **v3**（记账到 `d46b5d6`） | 10-14 ~ 10-16 | **38** ✓ | `143 files, +28721 / −3223` ✓ | `d46b5d6` |
| **v3 ~ HEAD**（含 v4~v8） | 10-14 ~ 10-23 | **78** ✓ | `320 files, +90146 / −4989` ✓ | `HEAD` |
| 全仓 | 10-03 ~ HEAD | **120** ✓ | — | — |

> ⚠️ **注：v1 行不可复核**。历史文档写的是 `44 files / +5891 / −470`，三种算法都对不上：
> 空树 → `1c65e94` 实测 `50 files / +13133 / −0`；逐提交累加 `131 / +14423 / −1290`；
> 剔 lockfile `47 / +5593 / −0`。而且 v1 期**没有任何文件被删**，`−470` 无从产生。
> 结论：这是不可复核的历史旧账，**不要拿它做任何统计**；`17 个提交` 那一项是可复现的。
> 该条当时指向的 v1 层 §8 注已随九层目录删除，结论以本注为准。

复跑：

```bash
git rev-list --count 1c65e94..b78de90          # 提交数
git diff --shortstat 1c65e94 b78de90            # 规模
```

## 5. 怎么复核这里的一切

```bash
git rev-list --count <A>..<B>     # 提交数
git diff --shortstat <A> <B>      # 规模（本文口径）
cd backend && uv run pytest --collect-only -q   # 用例基线（收集数，现取现算）
```

文档里出现的每个路径，`ls` 都必须能看见——这是本项目两次「写入报成功、次日消失」换来的纪律，
也是现行 `ARCHITECTURE.md` §5.6 与 `roadmap.md` §0.7 里「逐条 `Test-Path`」要求的由来。
写完必须 `ls` + `git status` 复核；提交前先 `git add -An .` 预演并经人确认。
