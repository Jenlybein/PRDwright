# v9 路线图：容器化

> 排期真源本文件；架构依据与决策取舍见本层 `ARCHITECTURE.md`。
> 任务编号用于日常排期（T19.x），版本号用于对外收口（v9.x，对照见 `README.md`）。

---

## 0 排期总原则

1. **先有判断依据，再让它跑起来。** 探针（T19.1）与排空（T19.2）排在镜像之前。
   镜像先做出来的话，之后每一次「重启一次试试」都会在没判断依据的形态上留一具 `running` 的尸体。
2. **文档先落，交付物后落。** 文档（T19.0）是第一笔：范围、契约、被否决的方案先定，
   后面六个阶段都往里填内容，不再临时 invent 一套目录。
3. **一份编排，全平台。** 不给 Windows 单独一份 compose（理由见 `ARCHITECTURE.md` §4.2）。
   任何「只在某个平台上改一下挂载」的想法，都先回到命名卷那条结论上。
4. **不可逆的动作排在最后。** 数据与密钥从第一天起就在卷里；备份（T19.6）必须早于
   第一次「删东西 / 改结构」的操作。备份没做成不许起栈。
5. **每一阶段都能单独验收。** 探针能单独打、排空能单独测、镜像能单独起。
   不出现「要等 compose 写完才知道探针对不对」的串联等待。

## T19.1 · 探针分工（v9.1）

**目标**：让「进程活着」「能否派活」这两件事各有各的端点，编排器有判断依据。

| # | 交付物 | 落点 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 生死探针 | `backend/src/backend/api/health.py` | `GET /healthz` 恒 200，不查库、不查配置、不发外部请求 |
| 2 | 就绪探针 | 同文件 | `GET /readyz` 判两件事：**库可写**、**技能包可加载**；任一不满足返回 503，响应体指出是哪一项 |
| 3 | 认证白名单 | `backend/src/backend/api/deps.py` | 两条路径进白名单：未登录访问得到 200/503，不是 401 |
| 4 | 用例（既有接缝） | `backend/tests/` 既有启动路径用例文件 | 坏依赖 → 503 且指认是哪项；好依赖 → 200；`/health` 仍恒 200 |
| 5 | 编排接线 | `deploy/` | `healthcheck` 指向 `/healthz`；就绪判断用 `/readyz` |

**为什么不复用 `/health`**：它恒 200、`status` 只有 `ok` / `degraded`，是「人看的详情页」。
把它配成「非 200 就重启」，会在技能包缺失这类**可降级**状态下把还能用的容器踢掉。

**风险**：白名单漏改 → 探针被鉴权拦成 401，表现为「容器永远不健康」。要让人一眼看出
是「路由不在白名单」而不是「服务坏了」：用例直接断言状态码。

**回滚**：删两条路由与白名单两行，`/health` 不受影响。

## T19.2 · 排空（v9.2）

**目标**：重启容器时，在途任务有**明确结论**，不留 `running` 的尸体。

| # | 交付物 | 落点 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 排空单元 | `backend/src/backend/services/job_service.py`（与 `job_runtime.py` 协作） | 可直接调用；不起子进程、不发真信号 |
| 2 | 信号接线 | `backend/src/backend/main.py` 的 `lifespan` 收尾 | `SIGTERM` → 就绪转 503 → 停止接收新任务 → 等在途 ≤30 秒 → 退出 |
| 3 | 终态口径 | 任务状态机 | 超时的在途任务落「**已取消**」（不是「失败」），并向 SSE 订阅者发一条错误事件 |
| 4 | 退出日志 | 同上 | 退出前记一条「本次重启取消了 N 个任务」，运维据此知道影响面 |
| 5 | 用例（既有接缝） | `backend/tests/` 既有任务用例文件 | 在途任务排空后被标成已取消并落了终态；排空可重复调用（第二次是空操作） |
| 6 | 编排配置 | `deploy/` | `stop_grace_period` **大于** 30 秒（留 flush 与退出余量） |

**为什么 30 秒是「等待上限」而不是「必须等满」**：任务都结束了就立刻退出，否则每次重启都白等
半分钟——这会让「重启很快」这件事变成一句假话。

**风险**：`stop_grace_period` 小于排空窗口时，容器会在排空走完前被硬杀，任务又变回
`running` 的尸体。这一条只能靠配置保证，所以写进契约（C-V9-8）。

**回滚**：排空是新增路径，去掉信号接线即回到 v8 的「下次启动 `reap_orphans` 收尾」。

## T19.3 · 应用镜像与启动脚本（v9.3）

**目标**：应用镜像跑起来就是「非 root、单 worker、技能包齐、密钥不对就拒绝启动」。

| # | 交付物 | 落点 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 应用镜像 | `deploy/` | 多阶段；`uv sync --frozen --no-dev`；`CMD` 里 `--workers 1`；含 `backend/migrations/`、`backend/alembic.ini`、`skills/` |
| 2 | 启动脚本 | `deploy/` | root 起步 → 把数据与日志目录属主校正到运行用户 → 降权 `exec`；**不跑迁移** |
| 3 | 运行用户 | 镜像 | 固定非 root uid；代码层只读，运行期不写镜像层 |
| 4 | 主密钥缺失即拒启动 | `backend/src/backend/core/crypto.py` 的启动校验 | 缺失时退出，并打印 `scripts/keygen/generate_keys.py` 的生成指引；绝不自动生成 |
| 5 | 技能包 | 镜像 | 三个技能包打进镜像；`PRDWRIGHT_SKILLS_STRICT=true` |
| 6 | 构建排除 | `deploy/`（构建忽略文件） | 排除 `node_modules`、`.venv`、本地 `.db` 与 `-wal`/`-shm`、`backend/.env`、`backend/secrets/`、`__pycache__`、`.git` |

**验收**：`docker run` 起来后 `/readyz` 200；把 `master.key` 移走后重启，容器退出并打印指引；
把 `skills/` 从镜像里拿掉（临时构建一次）后启动失败而不是降级。

**风险**：第 6 项里漏掉 `backend/.env` 或 `backend/secrets/` 会把密钥打进镜像层，
且镜像一旦被拉走就跟着走了。

**回滚**：删镜像定义即可，业务代码只多了一处启动校验。

## T19.4 · 静态站点镜像与反向代理（v9.4）

**目标**：三路请求由同一入口分派，且流式输出不被反代缓冲掉。

| # | 交付物 | 落点 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 静态站点镜像 | `deploy/` | node 构建两个前端产物 → `nginx:alpine`；`/admin/` 落在子目录 |
| 2 | 反向代理配置 | `deploy/` | `/`、`/admin/`、`/api/`、`/healthz`、`/readyz` 五条路由；SSE 三行（`proxy_buffering off`、长 `read_timeout`、`gzip off`） |
| 3 | 缓存策略 | 同上 | `assets/*` 长缓存；`index.html` 必须 `no-store` |
| 4 | 前端基址 | **不改前端** | 两个前端仍用相对路径 `/api`（Vite 的 `import.meta.env` 是构建期替换） |
| 5 | 验收 | 起栈后 | 首页 200、`/admin/` 200、`/api/...` 经反代可达、SSE 逐字出现不是最后一次性刷出 |

**风险**：反代路径前缀与前端 `base` 不一致会表现为「页面白屏、资源 404」，
而镜像本身构建成功。验收必须用浏览器打一次 `/admin/`，不能只看构建日志。

**回滚**：删镜像定义即可，前端代码未改。

## T19.5 · compose 编排与部署 README（v9.5）

**目标**：`docker compose up -d` 能起来，起来之后数据落在卷里，README 的第一条命令就能跑通。

| # | 交付物 | 落点 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 编排 | `deploy/` | 两服务；`api` 只 `expose` 不 `ports`；三个命名卷；宿主只发布 80；`stop_grace_period` |
| 2 | env 样例 | `deploy/` | 每个变量一行中文说明 + 默认值；`CORS_ORIGINS=` 为空并注释；`PRDWRIGHT_MASTER_KEY_PATH` 指向只读卷 |
| 3 | 部署 README | `deploy/` | 备 `.env` 与主密钥 → `docker compose up -d` → 打开 `/` 与 `/admin/`；**备份纪律写在显著位置** |
| 4 | 危险命令警示 | 同上 | `docker compose down -v` 标注为「连数据一起删」 |
| 5 | 验收 | 全新机器 | 起栈后 `/`、`/admin/`、`/api/...` 三者可达；`/readyz` 200；重启后数据仍在 |

**风险**：`.env` 样例漏一个变量 → 读者起栈失败却不知道为什么。样例要覆盖 `ARCHITECTURE.md`
§4 提到的全部项（数据路径、日志目录、主密钥路径、skills 严格模式、`CORS_ORIGINS`、`TZ`）。

**回滚**：`docker compose down`（不带 `-v`）后删文件即可，卷里的数据保留。

## T19.6 · 备份脚本（v9.6）

**目标**：一条命令得到一份**能验证完整性**的备份。

| # | 交付物 | 落点 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 备份脚本 | `deploy/` | 一条命令；SQLite 在线备份（`VACUUM INTO` 到新文件），不设第二种后端 |
| 2 | 产物 | `deploy/` 下备份目录（版本控制忽略） | 文件名带日期；旁边一份同名 `.sha256` |
| 3 | 自检 | 同上 | 能打开 + `PRAGMA integrity_check` = `ok` + 读得到 `alembic_version`；任一失败即非 0 退出 |
| 4 | 运行环境 | `backend/.venv` | 只用 Python stdlib，不要求宿主机装 `sqlite3` CLI |
| 5 | 演练记录 | 本文件附录 | 备份 → 在另一目录恢复 → 服务能读起来并答 `/readyz` 200 |

**风险**：只写「备份成功」而不自检，等于把「备份存在」当成「备份可用」。
v7 已经踩过一次（`VACUUM INTO` 与 `cp` 的差别），这次把自检写进脚本的退出码。

**回滚**：删脚本即可；产物是只增不改的文件，无代码语义变化。

## T19.7 · CI：镜像构建与整栈冒烟（v9.7）

**目标**：让「镜像能构建」「栈能起来」有证据，而不是承诺。

| # | 交付物 | 落点 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 构建 job | `.github/workflows/ci.yml` | 构建两个镜像；tag 用 `git describe`；**不推送** |
| 2 | 整栈冒烟 | 同上 | 起 compose → 轮询 `/readyz` 直到响应体 `status == "ready"`（只看 200 会假绿）→ 取 `/` 与 `/admin/` → 走反代打一次健康端点 → 断言 api 的 PID 1 以 uid 10001 运行 → 拆栈 |
| 3 | 时长 | 同上 | 单 job 内完成，约 2–3 分钟 |
| 4 | 失败可诊断 | 同上 | 拆栈放 `always()`；失败时保留容器日志 |

**为什么不做业务链路**：登录 → 生成要真模型调用，在 CI 上既慢又不稳。
容器冒烟只回答一个诚实的问题：**这套栈能不能起来**。业务链路由既有 1000+ 用例守。

**风险**：CI 起栈占端口 80。要么用 compose 的端口映射换到高位端口，要么在 job 里改一份
临时覆盖配置——选哪种要写在 job 的注释里，别让下一个人猜。

**回滚**：删 job 即可，不影响既有三个 job。

## 债务与遗留（本期不做，登记备查）

- **PostgreSQL / MySQL 接入、全库真类型化**：不做（固定 SQLite）。
- **k8s / Swarm、多架构镜像、容器内 TLS、热重载容器、业务链路自动化**：见 `ARCHITECTURE.md` §1.3。
- **就绪探针不覆盖「模型供应商配置是否可用」**：依赖外部网络，高频探针会烧额度、会误报；
  它仍在 `/health` 三项体检里，由人看。
- **镜像体积未做优化**：本期只去掉构建工具与 dev 依赖；按协议拆镜像是「有需要时」的事。
- **排空的 30 秒是待校准值**：用一条真实长任务测出实际耗时后回填（见下表）。

## 交叉纪律

1. **路径即承诺**：写进文档的每个仓库路径都要 `ls` 可见；`deploy/` 在 T19.3~T19.6 期间逐步成形，
   收口时逐条复核（C-V8-3 照旧成立）。
2. **改探针或排空，同步改 `ARCHITECTURE.md` §5**：契约 C-V9-7 / C-V9-8 是同一个提交里的东西。
3. **一次改动要收口**：代码、架构文档、路线图三者同步，谁都不滞后。
4. **提交信息用中文**；容器冒烟是这一版唯一新增的测试接缝，不要再加第二个。
