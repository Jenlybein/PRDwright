# v9 · 容器化

> **一句话**：把 v8 图纸里那套「两个镜像 + 命名卷 + 探针 + 排空」，落成一条
> `docker compose up -d` 就能起的**交付物**——一台装了 Docker 的机器，照 `deploy/` 的 README
> 备好 `.env` 与主密钥，就能登录、能生成、能重启、能备份。
>
> **下层**：`../v1/` ~ `../v8/`。v9 **不改**业务能力、不改数据契约、不改前端交互，
> 只改「怎么被部署」：镜像、入口、卷、探针、重启语义。
>
> 阶段全貌与已核实的时间线数字：**`../README.md`**

## 已拍板的决策

| # | 当时的选项 | 决定 |
| --- | --- | --- |
| 1 | 切几个容器：① 一个容器塞 Nginx + uvicorn；② 前后端各一个镜像；③ 再加一个 DB 容器 | **取 ②**：静态站点镜像（Nginx + 两份 dist）+ 应用镜像（uvicorn + SQLite）。不加 DB 容器——本期仍是文件库，独立 DB 容器没有对象 |
| 2 | 数据怎么持久化：① 宿主目录挂载；② Docker 命名卷 | **取 ②**。Windows 上的 bind mount 会丢文件锁与 `-shm` 的 mmap，SQLite 随机报 I/O 错误甚至静默损坏；命名卷在虚拟机内部是原生文件系统 |
| 3 | 要不要给 Windows 一份覆盖编排 | **不要**。只做一份 compose，全平台跑命名卷——「哪些目录要持久化、怎么挂」这份知识只写一次 |
| 4 | 技能包：① 挂载；② 打进镜像 | **取 ②**。镜像即完整交付物，要换技能就重建镜像；挂载会让「镜像与技能包版本不一致」成为可能 |
| 5 | 探针：① 直接拿 `/health`；② 新增生死 + 就绪两条 | **取 ②**。`/health` 恒 200（v7 契约），当探针等于永远健康；就绪探针要查「库可写 + 技能包可加载」两件真事 |
| 6 | 重启时在途任务：① 硬杀，下次启动 `reap_orphans` 收尾；② 排空 | **取 ②**。摘流 → 等最多 30 秒 → 超时取消落终态并发错误事件。硬杀会让用户看到「任务凭空消失」 |
| 7 | 主密钥缺失时：① 自动生成一把；② 拒绝启动 | **取 ②**。自动生成会让旧密文永久解不开，而且当场没人发现 |
| 8 | 镜像要不要推送到仓库 | **不推送，只构建**。没有凭据通道，而「镜像还能不能构建」这件事本身此前无人守；tag 用 `git describe` 便于对账 |

## 与 v8 的关系

v8 只讲方言收敛与清理，v9 只讲容器形态——两层不再混着讲同一件事：

| v8 的结论 | v9 是否变 | 为什么 |
| --- | --- | --- |
| 方言收敛在 `core/dialect.py`（`C-D1~C-D6`） | 不变 | 本版不碰数据库 |
| 结构对拍保留 `PRAGMA` 实现 | 不变 | 与部署形态无关 |
| 大段文本 60KB 闸门（`C-V8-1`） | 不变，且容器里更需要它 | 超长内容在目标库上的失败更难定位 |
| 删列 / 改类型不可逆，回滚 = 恢复备份（`C-V8-2`） | 不变，且备份脚本按后端分派 | 换库那天备份链不能断 |
| 文档路径必须 `ls` 可见（`C-V8-3`） | 不变 | 本版最容易犯的错就是「文档承诺、文件没落盘」 |

**术语同步改了一次**：`GLOSSARY.md` 里「方案」的释义由「一次完整工作的容器」改为
「一次完整工作的承载单元」，「容器」一词从此**只指 Docker 容器**。本层 `ARCHITECTURE.md`
开头有一条口径声明，写在读者最可能误会的地方。

## 读完你会知道的三件反直觉的事

1. **容器化不会让它更耐挂，反而更容易丢在途任务。** 裸机上 `systemctl restart` 至少还看得见
   日志、还能先看 `running` 列表；容器里 `docker compose up -d` 重建容器，正在跑的生成任务
   直接消失。所以这一版真正承重的不是 Dockerfile，是 `stop_grace_period` 与排空。

2. **SQLite 放进容器，最危险的不是容器，是挂载方式。** 用 Windows 目录做 bind mount 会拿到
   `disk I/O error`——不是配置写错，是那层文件系统不支持 SQLite 需要的文件锁与 `-shm` 的 mmap。
   这一条在开发机上就会遇到，不必等上线；而它只能靠换文件系统（命名卷）解决。

3. **「健康」这个词在这版被拆成了三件事。** `/health` 说「能不能用」（恒 200、三项体检），
   `/healthz` 说「进程还活着」（恒 200），`/readyz` 说「现在能派活给它吗」（不 OK 就 503）。
   把三件事混成一个端点，就会在技能包缺失时把还能用的容器反复踢掉——v7 的文档已经踩过一次。
