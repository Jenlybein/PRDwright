## 已拍板的决策

| # | 当时的选项 | 决定 |
| --- | --- | --- |
| 1 | 方言散在各仓库，还是收进一个模块 | **收进 `core/dialect.py`**。`api/` / `services/` / `repositories/` 不再出现数据库品牌 |
| 2 | 可移植性一次做到位，还是分两段 | **分两段**。本期只做「接口收敛」（零行为变化、可用现有用例自证）；换列类型与数据搬运归换库那次 |
| 3 | 结构对拍：① 换 `sqlalchemy.inspect` 求方言中立；② 保留 `PRAGMA` 实现 | **取 ②**。实测 `inspect()` 不返回外键的 `ondelete`，换过去会让「级联规则」这项判据**消失**而不是变宽松 |

## 与 v7 的关系

v8 **不动** v7 定下的部署形态与运维契约——本层只把「怎么与数据库对话」换个写法，
再删掉一批没人读的东西。v7 的结论原样成立：

| v7 的结论 | v8 是否变 | 为什么不变 |
| --- | --- | --- |
| 单域名 + 路径前缀（`/`、`/admin/`、`/api/`） | 不变 | Cookie 是 host-only，跨子域会「登录了但调 API 401」 |
| 单 worker 硬约束 | 不变，且更硬 | `_RUNTIMES` / `JobBus` / runtime 快照 / 连接池都在进程内；本层两件事都不引入跨进程状态 |
| 四目录分离（代码 / 数据 / 静态 / 日志） | 不变 | 「回滚代码」与「保住数据」仍必须是两个动作 |
| 回滚 = 恢复备份 | 不变，且删列场景同样适用 | 迁移只追加，回退代码后的真实状态是「新结构 + 旧代码」（C-V8-2） |
| `VACUUM INTO` 备份 | 不变 | 开了 WAL，`cp` 会静默缺最近写入 |
| SSE 三行 + `: ping` 心跳 | 不变 | 分章生成 + 审核之间有长静默期 |
| 重启 = 跑迁移 | 不变（`lifespan` 里 `prepare_schema`） | 本层没有第二个迁移入口 |

## 读完你会知道的三件反直觉的事

1. **方言收敛的最大产出不是「能换库」，而是它顺手否掉了自己的一半计划。** 原打算把结构对拍
   从 `PRAGMA` 换成 `sqlalchemy.inspect()` 求方言中立——实测发现 `inspect()` 不返回外键的
   `ondelete`，换过去等于让「级联规则」这项判据**消失**（不是变宽松）。收敛的实际收益因此
   回到它真正的来源：三处 upsert 收进一个模块、业务三层不再出现数据库品牌。

2. **「留着备查」是仓库里最贵的一句话。** 退役列的用途从未兑现（无导出、无页面读它），
   但每个读代码的人都要为它判断一次；判断天天发生，删除只发生一次。所以清理的判据是
   三条同时成立才动，且「被旧文档说是死的」不算证据——`AppDialog.vue` 就是被文档写成
   "零外部引用"、实际仍被 `ReviewStage.vue` import 的例子。

3. **可移植性是分两段的，而第二段现在没有目标库。** 本层只做到「接口干净」（可用现有用例
   自证）；换列类型、数据搬运、以及「两个后端各跑一遍」的测试矩阵，都要等目标库定下来，
   否则每个决策都只能靠猜，猜错的表现为「上线那天才炸」。
