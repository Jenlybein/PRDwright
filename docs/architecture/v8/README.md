# v8 · 容器化与方言收敛

> **一句话**：把 v7 那套「裸机 + systemd + Nginx + 手写目录」的部署形态，
> 收进一个 `docker compose up` 就能起的镜像集合；同时把「这个项目跑在 SQLite 上」
> 这件事从散落各处的写法，收进**一个模块**。
>
> **下层**：`../v1/` ~ `../v7/`。v8 **不改**任何业务能力、不改数据契约、不改前端交互，
> 只改「怎么被部署」与「怎么与数据库对话」。
> 阶段全貌与已核实的时间线数字：**`../README.md`**

## 已拍板的决策（详见 [`../../adr/`](../../adr/README.md)）

| # | 当时的选项 | 决定 | 记录 |
| --- | --- | --- | --- |
| 1 | 方言散在各仓库，还是收进一个模块 | **收进 `core/dialect.py`**。`api/` / `services/` / `repositories/` 不再出现数据库品牌 | ADR-088 |
| 2 | 可移植性一次做到位，还是分两段 | **分两段**。本期只做「接口收敛」（零行为变化、可用现有用例自证）；换列类型与 ETL 归换库那次 | ADR-089 |
| 3 | 容器切几个：① 一个容器塞 Nginx + uvicorn；② 前后端各一个镜像 + Nginx；③ 再加一个 DB 容器 | **取 ②**：`web`（Nginx + 两个 dist）+ `api`（uvicorn + SQLite）。不加 DB 容器——本期不换库 | ADR-090 |
| 4 | 数据库：① 仍用 SQLite；② 只支持 MySQL；③ 两个后端都一等、部署时自选 | **取 ③**。SQLite 覆盖零运维场景（个人自部署），MySQL 覆盖"已有 DBA/已有实例"场景；由 `DATABASE_URL` 决定。ADR-091 的"换库推迟"因此作废 | ADR-097 |
| 5 | 健康检查：① 直接拿 `/health`；② 新增 liveness / readiness 两条 | **取 ②**。`/health` 恒 200（v7 契约），当探针等于永远健康 | ADR-092 |
| 6 | 前端 API 基址：① 构建期注入 env；② 只允许相对路径 | **取 ②**。Vite 的 `import.meta.env` 是构建期替换，容器里改环境变量改不动它 | ADR-093 |
| 7 | 结构对拍：① 换 `sqlalchemy.inspect` 求方言中立；② 保留 `PRAGMA` 实现 | **取 ②**。实测 `inspect()` 不返回外键的 `ondelete`，换过去会让「级联规则」这项判据**消失**而不是变宽松 | ADR-094 |
| 8 | 大段文本上限：① 按字符（6 万字）；② 按字节（60KB） | **取 ②**。中文一字 3 字节，按字符会让中英文容量差三倍；闸门在 `core/limits.py`，超限写入前报错 | ADR-095 |
| 9 | 退役列（`solutions.data`、`model_providers.builtin`）：① 留着标 deprecated；② 直接删 | **取 ②**。「保留为了不重建表」的前提已随 Alembic 消失；保留的成本是每个读代码的人多一次判断 | ADR-096 |

## 与 v7 的关系

v8 **不推翻** v7 的任何部署结论，只换执行方式：

| v7 的做法 | v8 的做法 | 为什么不变 |
| --- | --- | --- |
| 单域名 + 路径前缀（`/`、`/admin/`、`/api/`） | 不变 | Cookie 是 host-only，跨子域会「登录了但调 API 401」 |
| 单 worker 硬约束 | 不变，且容器**只能 1 副本** | `_RUNTIMES` / `JobBus` / runtime 快照 / 连接池都在进程内 |
| 四目录分离（代码/数据/静态/日志） | 映射成三个命名卷 + 镜像内只读代码 | 「回滚代码」与「保住数据」仍必须是两个动作 |
| 回滚 = 恢复备份 | 不变，追加「回滚镜像 tag」 | 迁移只追加，回退代码后的真实状态是「新结构 + 旧代码」 |
| `VACUUM INTO` 备份 | 不变，改为备份到独立的卷 | 开了 WAL，`cp` 会静默缺最近写入 |
| SSE 三行 + `: ping` 心跳 | 不变，容器网络里多一跳 | 分章生成 + 审核之间有长静默期 |
| 重启 = 跑迁移 | 不变（`lifespan` 里 `prepare_schema`） | 容器重启同样是「新进程 + 旧库」 |

## 读完你会知道的三件反直觉的事

1. **容器化不会让它更耐挂，反而更容易丢在途任务。** 裸机上 `systemctl restart` 至少
   还看得见日志；容器里 `docker compose up -d` 重建容器，正在跑的生成任务直接消失。
   所以 v8 的「编排」里真正重要的不是 `Dockerfile`，是 `stop_grace_period` 与排空。

2. **SQLite 放进容器，最危险的不是容器，是挂载方式。** 用 Windows 目录做 bind mount
   会拿到 `disk I/O error`——Docker Desktop 的 grpc-fuse 不支持 SQLite 需要的文件锁
   与 WAL 的 `-shm` mmap。必须用命名卷。这一条在开发机上就会遇到，不必等上线。

3. **方言收敛的最大产出不是「能换库」，是结构对拍换了工具。** `schema_snapshot.py`
   原来用 `PRAGMA` 检查 SQLite 的库结构——工具与被检查对象用了同一个数据库的私有接口。
   换成 inspector 之后，「迁移对不对」这件事才第一次有独立证据。
