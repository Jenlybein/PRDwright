社区二手交易 App 产品需求文档

版本 v0.3 ｜ 适用范围：iOS / Android / 微信小程序

1. 产品概述

1.1 一句话定义

把「同一个小区、能下楼见面」当成二手交易的前提：买卖双方的距离以米计，交易从「先付款、等快递」变成「下楼看一眼，当场验货」。

1.2 要解决的问题

  • 跨城交易没有验货机会。先付款后收货，货不对板时维权成本远高于商品本身。
  • 同城也懒得跑。距离十几公里、时间对不上，闲置最终被扔进垃圾站。
  • 发布成本高。拍照、想标题、定价、选分类，四步劝退一半人。

1.3 本期不做的

  • 担保交易与平台垫付：本期只做见面交易，资金不经过平台。
  • 跨城物流与快递下单。
  • 直播带货、拍卖与竞价。

2. 目标用户与场景

2.1 用户画像

  • 搬家或毕业的租客。一屋子东西带不走，只求一周内清空：对价格不敏感，对速度敏感。
  • 带娃家庭。孩子长得快，童车、玩具、绘本大量剩余，愿意低价换空间。
  • 退休业主。家里有闲置，但不熟悉信用分与快递流程，更信「当面看一眼」。

2.2 典型场景

  1. 晚上九点，用户在客厅拍下一辆婴儿车，30 秒内发布；第二天上午，同栋楼的邻居上门取走。
  2. 买家在「附近在售」按距离排序，看到 200 米外的一台显示器，站内私信约在地下车库验货。
  3. 卖家临时反悔，买家一键举报并拉黑，此后不再看到该用户的任何在售商品。

3. 核心功能

核心功能围绕一条主线展开：发布 → 附近曝光 → 私信约看 → 当面交易 → 评价与治理。

3.1 发布闲置

把「拍照 → 自动识别分类 → 定价建议 → 同小区可见」四个动作收敛成一条流水线：

  • 拍照即发布。一次最多 9 张，第一张自动作为封面，拍完直接进预填页，不再单独设「新建商品」入口。
  • 自动识别分类。模型给出 Top 3 类目并预填标题关键词，用户可一键改选；置信度低于阈值时不预填，避免把错类目写进标题。
  • 定价建议。取同小区同类目近 90 天成交价的中位数，给出「好卖 / 均衡 / 高卖」三档与各自的预计成交时长。
  • 同小区可见。默认仅同小区加周边 1 公里，可按需放开到同城；可见范围写在商品卡片上，不做隐藏设置。

3.2 附近在售列表

按距离分三档（500 米、1 公里、3 公里），默认展示 1 公里内、按发布时间倒序；同一小区单独成组置顶，避免和隔壁小区的信息混在一起。
