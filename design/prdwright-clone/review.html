PRD 文档

社区二手交易 App · 产品需求文档

版本 v3 · 2026-11-21 · 由 PRDwright 生成，待确认

1. 产品概述

一个只服务「同一个小区」的二手闲置交易 App：邻居把不用的东西挂出来，楼上楼下的人下楼就能拿走，不寄快递、不到付运费。

  • 产品目标：让同一小区的邻居之间安全、快速地完成闲置物品的转让。
  • 平台：iOS / Android App + 微信小程序，三端共用同一套账号与接口。
  • 本期 MVP（五件事）：发布闲置、附近在售列表、站内私信、交易评价、举报与拉黑。
  • 本期不做：在线支付、跨城邮寄、商家入驻与竞价。

衡量指标：新发布的闲置在 24 小时内拿到至少 1 次有效询价；成交后双方互评率不低于 40%。

2. 目标用户

25–40 岁城市社区住户。手机不离手、习惯用手机处理生活琐事，但不认为「卖个二手」值得专门学一套流程。

  • 卖家（主力）：换季、搬家、孩子长大后腾出来的空间需要清理；东西还能用，扔掉可惜，挂到综合二手平台又要打包、寄快递、来回谈价，最后往往直接丢掉。
  • 买家（主力）：想要「下楼 5 分钟拿到」。一件 30 元的物品，运费 8 元、还要等 3 天，比自己跑一趟更贵。
  • 共同顾虑：不愿意把手机号、门牌号交给陌生人；担心对方放鸽子，或者东西和描述不符。

因此撮合的重心落在「小区 + 站内私信」：先确认是邻居，再决定要不要下楼。买家在列表里看到的就是「离我几百米」的真实物品，而不是一个需要物流的 SKU。

3. 核心功能

3.1 发布闲置

拍照（最多 9 张）、标题、价格、成色、自提地点。自提地点只到「小区 + 楼栋」，不收集精确门牌号——这一条同时是隐私承诺和审核口径。

3.2 附近在售列表

按距离排序，默认先看本小区，超过 3km 的物品不进列表。卡片只给价格、成色、小区名和第一张图，点进去才看详情与卖家。

3.3 站内私信

买家从列表或详情进入私信，问成色、约时间。开聊前需完成实名；会话中出现手机号、微信号时自动打码，改为提示「用站内私信联系」。

3.4 交易评价

一笔交易一条评价，双方都评完才同时可见。不打星级，只勾三项：「描述相符」「守时」「好沟通」——打分会把邻居关系变成商家评分。

3.5 举报与拉黑

举报进人工队列，24 小时内处理；拉黑后双方在列表与私信里互相不可见，已有会话转为只读。

4. 技术方案

  • 认证：手机号 + 短信验证码登录，首次登录即建号，不设密码。
  • 后端：FastAPI + SQLModel，接口按 REST 组织，统一前缀 /api/v1。
  • 存储：Postgres 存业务数据；图片走对象存储，库里只保存 key 与缩略图 URL。
  • 部署：Docker Compose 编排 api / db / nginx 三个容器，Nginx 反代并终止 TLS。
