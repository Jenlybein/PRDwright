# api-docs-generator

根据 PRD 正文产出配套的 API 接口文档。与旧实现的最大区别：**不再做 RAG 检索**——
旧链路会把团队接口规范库按 PRD 关键词「挑几条」塞给模型，既依赖索引质量、又在部署时
静默降级；现在团队的全部接口规范与历史接口示例都放在 `references/api-specs.md`，
生成时**整段注入**提示词，由模型自行取舍，对齐更稳定、也不存在「检索没命中就悄悄丢规范」。

## 执行流程

1. 读取 PRD 正文，提炼其中涉及的接口能力（不要凭空增加 PRD 没提到的接口）。
2. 读取 `references/api-specs.md`，将其中的团队规范（响应信封、错误码、分页、鉴权、
   命名、时间/金额格式、SSE、幂等等）与历史接口示例作为设计时的对齐依据。
3. 按「概述 → 错误码约定 → 接口列表 → 数据模型 → 附录」输出接口文档。
4. 凡是 `api-specs.md` 已有明确约定的（如统一响应结构、5 位错误码、lowerCamelCase 字段名），
   必须沿用，不要另立一套；规范与 PRD 冲突时以 PRD 的业务事实为准，并在输出里说明取舍。

## 资源

- `references/api-specs.md`：团队接口规范与历史接口示例（生成时整段注入提示词）。
