## 三、输出要求

1. **提示词设计原则**：结合本产品业务，说明这套提示词的设计思路与通用约束。
2. **提示词清单**：按使用场景分组，每个提示词包含：

   - 完整提示词正文（可直接复制使用）
   - 输入变量说明
   - 预期输出示例
3. **变量约定**：统一说明占位符写法（如 `{{变量名}}`）。
4. **调优建议**：常见问题与对应的调整方向。

## 四、写作要求

- 提示词必须和本产品的真实业务场景绑定，不要生成通用的万能模板。
- 每个提示词都写清角色、任务、约束、输出格式四个要素。
- 提示词正文用代码块包裹，避免转义和格式丢失。
- **接口文档那一节可能是一句「本次未提供」的说明**：那是已知缺失，不是漏读——照常按 PRD
  写即可，不要去猜接口长什么样。若确实提供了接口文档，则提示词里涉及的接口路径、字段名与
  职责划分都要与它保持一致；两者冲突时以 PRD 为准。
- 直接输出 Markdown 正文。
